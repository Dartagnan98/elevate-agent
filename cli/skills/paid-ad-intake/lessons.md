[2026-06-24] | The original ad-hoc import hard-coded "450 Main Street" + "that one has an accepted offer" into all 174 first-touch drafts, regardless of which ad each lead clicked. | NEVER reference a specific listing unless the lead record has a real street address. MIR's "Listing" field is often generic ("Custom Listing") — treat that as unknown and use the safe generic opener. The script's ADDR_RE gate enforces this; do not loosen it.
[2026-06-24] | The dashboard `paid-ads` source looked unregistered because source_connector_modules/source_catalog.py (elevate-current-src) had no paid-ads blueprint. | The RUNNING app loads the monolith ~/Elevation/elevate_cli/source_connectors.py (which HAS paid-ads), not the modular catalog. To verify what the live app actually serves, run build_source_inbox_response with the app python (PYTHONPATH=~/Elevation:<bundle>/cli). Don't trust elevate-current-src for runtime truth.
[2026-06-24] | The realtor wants leads who clicked a specific-listing ad (Listing eXposure - <address>) to get a property-specific message, using her prepped wording. | `build_draft` uses a status-aware listing-click template for these: "Hi {first}, it's {realtor first name} from {brokerage}. I saw your name pop up after you viewed my listing at {address}." Then: if the listing is under accepted offer / sold (per sold-listings.md) → her verbatim "We have an accepted offer on this one, but I am happy to send you some other similar homes if you like. Or were you just browsing?"; if active (active-listings.md) → "I'd be happy to get you in to see it, or send you some other similar homes if you like. Or were you just browsing?". Status defaults to AVAILABLE when unknown — NEVER claim an accepted offer on an active listing (scares off the lead). `listing_status()` + `clean_address()` handle this. Address comes from `trusted_listing()` (program name first, never the contaminated listing field).
[2026-06-24] | gws Gmail CLI prints a keyring/decrypt warning to stderr but still returns valid JSON on stdout. | Parse stdout from the first "{"; don't treat the stderr warning as failure.
