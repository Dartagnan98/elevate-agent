# BC listing documents and Matrix links

Apply this checklist to new listings and relists, in both initial preparation and later media updates. Use the existing matched deal, listing Google Drive folder and Matrix/Xposure draft.

## Documents / Supplements tab

| Item | Required handling |
|---|---|
| Current title PDF | Verify it is uploaded in Matrix Documents/Supplements. If the realtor already uploaded it, verify and retain that copy; do not upload it again. |
| BC Assessment PDF | Save the property-matched PDF in the listing Google Drive folder and upload it in Matrix Documents/Supplements. Assessment values copied into fields are not a substitute for this PDF. |
| Property Information Report PDF | Obtain the actual report from the configured property source, save it in the listing Google Drive folder, and upload it in Matrix Documents/Supplements. A summary JSON or property-notes artifact is not the report. |
| Floor-plan PDF, when available | Save/verify the PDF in the listing Google Drive folder and upload it in Matrix Documents/Supplements. Also add its shareable PDF URL in the links section below. |

Resolve the current title from the existing deal/Drive documents before ordering another one. Confirm property address/unit and PID where available, report identity and current applicability. Verify actual PDF bytes/readability, not just a filename or a cloud placeholder. If a required title, assessment or Property Information Report cannot be obtained, finish independent work and record that specific missing document and next action; preparation remains partial.

Before uploading, inspect the saved Documents/Supplements rows. Match document kind, property, filename/version and actual contents when needed; reuse correct existing uploads, including those added manually by the realtor. Select the portal's actual supported document category, use a clear description and verify the uploaded PDF by reopening/downloading it. Do not duplicate the document on retry or substitute a stale prior-listing report without checking applicability.

## Links section near the bottom of Matrix

Use the current visible labels; verify the portal's link type and saved field rather than assuming historical input IDs.

- **Floor plans:** add a shareable viewer/download URL to the actual floor-plan PDF. Uploading the PDF in Documents does not fulfil this separate link requirement. If sharing must be enabled, grant viewer access only to the intended floor-plan file; do not expose the entire client folder or grant edit access. Verify the link works for the intended listing audience without the agent's private login.
- **Listing landing page:** add the verified canonical URL for this property's published landing page. Do not use a guessed URL, local preview, expiring private preview token or another property's page. If the page is still awaiting its publishing step, keep a visible pending-link task and update the same listing after the real URL is available.
- **Property video, when available:** add the verified shareable property-video/tour URL in the suitable video/tour/link field. Confirm the address/content, intended audience access and playback. A local file path is not a shareable URL.

Floor plans and video are conditional assets. Record confirmed absence as not available; do not invent files or treat an unavailable optional asset as a mandatory missing input. If an asset is expected but has not arrived, record it as pending. When a floor plan, landing page or video becomes available later, resume the existing listing and update its documents/links without creating a new listing or restarting the entire stage.

## Save, reopen, and hand off

Save the preparation through Save as Incomplete / the supported save action. Reopen the correct listing and verify each document row and each saved link. Preserve the existing final-publication approval boundary.

Record a document/link manifest in the result artifact: item, source/property match, Drive file ID/path, Matrix document category/row or link label, saved URL where applicable, verification evidence, and status (verified/already_present/pending/not_available/failed). Use existing supported Admin checklist fields; keep per-item detail in the artifact rather than inventing checkbox IDs. Preparation is complete only when required documents and available assets/links have saved-record proof, with any genuinely pending later asset explicitly handed off.
